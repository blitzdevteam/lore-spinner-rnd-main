## What This Was

Two adaptation pipeline deliverables were being produced correctly but never
read during live gameplay. The runtime game loop was ignoring them entirely.

**`choice_consequence_map`** (on `session_adaptations`) — produced by
`ConsequenceMappingAgent`. Contains per-choice, per-path (A/B/C) consequence
data: how the narrator should echo the choice, what payoffs to honour next
session, what the next session opening should look and feel like if the
player took this path, fold-back guidance, hard limits, consequence visibility
targets (make visible within 2 responses). Also contains `freeform_guidelines`
(12 entries — 4 choices × 3 paths) with narrator behavioural instructions.

**`session_close_design`** (on `session_adaptations`) — produced by
`SessionCloseAgent`. Contains the authored session ending: resolution prose
(120–200 words), hook transition, a three-option session-end choice with
`next_session_opens` per option, and a final line. Also contains a stickiness
audit (payoff test, return driver test, overnight test).

Before this release: the model improvised both the session close and the
downstream consequence of player choices. `defining_choice_id` was stored on
the `game` record but the consequence map was never consulted. Every player
started the next session with the same generic handoff regardless of their
choices.

## What Changed

### 1. `runtime-narrator-template.blade.php`

Two new injection point tokens added to the pre-built narrator template.

**Section 10A (new, after Section 10):**
```
### SECTION 10A: CONSEQUENCE ECHO [RUNTIME]
[CONSEQUENCE_ECHO_INJECTION_POINT]
```
Receives the active consequence guidance block on every turn. Empty string
when no defining choice exists yet (session 1, turn 1).

**Section 16 (updated):**
```
[SESSION_CLOSE_INJECTION_POINT]

When no authored close block is injected above: [original fallback instruction]
```
Receives the authored close block (resolution prose + session-end choice)
only on the aftermath turn — when `is_climactic_choice` was set true on the
previous turn. Falls back to the original hardcoded instruction when empty.

These tokens live in the pre-built `runtime_narrator_prompt` stored in the
DB. Existing stored prompts do not have the tokens yet — they degrade
gracefully (strtr finds nothing to replace, prompt returned unchanged). A
`RuntimeNarratorAssemblyJob` re-run per story backfills them.

### 2. `app/Services/ChaosEngineService.php`

**`loadSessionContext()` signature updated:**
```php
public function loadSessionContext(
    Story $story,
    int $sessionNumber,
    ?string $openingHandoff,
    ?array $resolvedConsequencePath = null,   // NEW
    ?array $sessionCloseDesign = null,         // NEW
): ?array
```
Both params are optional (default null) so all existing callers continue
working without change.

Returns two new keys in its array:
- `resolved_consequence_path` — the matched A/B/C path merged with its freeform_guidelines entry
- `session_close_design` — the authored close for this session

**`renderSystemPrompt()` signature updated:**
```php
public function renderSystemPrompt(
    ...existing params...,
    bool $isClimacticThisTurn = false,   // NEW
): string
```
Default false — all existing callers unaffected.

Inside the method, both new tokens are resolved and substituted on every call
alongside the existing four tokens. `$closeBlock` is empty string unless
`$isClimacticThisTurn` is true.

**New public method: `resolveConsequencePath()`**

Given a `defining_choice_id` (e.g. `"S2_C3"`), `defining_choice_line`, and
the `choice_consequence_map` array, returns the matched path merged with its
`freeform_guidelines` entry — or null if unresolvable.

Resolution logic:
1. Find the `branching_consequences` entry whose `choice_id` matches (case-insensitive).
2. Match the player's `defining_choice_line` against `defining_line_captured`
   in each path using a normalised substring check.
3. Fuzzy fallback to the first path if line matching fails (should not happen
   if adaptation ran correctly).
4. Find the `freeform_guidelines` entry for the same `choice_id` + resolved
   `path_label` (A/B/C) and merge it into the path array.

**New private method: `buildConsequenceEchoBlock(?array $path): string`**

Formats the resolved path into a narrator guidance block. Includes:
- `current_session_echo` — what to echo this session
- `next_session_payoff` — what payoffs to honour
- `narrator_behavior` — how to surface the past choice going forward
- `consequence_visibility` — what changes, when to make it visible, how the player perceives it
- `fold_back_acknowledge` / `fold_back_redirect` — fold-back guidance for out-of-scope player actions
- `hard_limits` — StoryGuard violations at this node

Returns empty string when `$path` is null.

**New private method: `buildSessionCloseBlock(?array $closeDesign): string`**

Formats the authored session close into a narrator instruction block. Includes:
- `resolution_prose` (labelled: deliver in author's voice)
- `hook_transition`
- `session_end_choice` (choice_question + option_a/b/c text + final_line)

Returns empty string when `$closeDesign` is null.

### 3. `app/Http/Controllers/User/Game/PromptController.php`

On every player turn (`store()`):

1. Checks `$game->defining_choice_id` and `$game->defining_choice_line`.
2. If present, extracts the session number from the choice_id (`S2_C3` → 2),
   loads that prior session's `choice_consequence_map` from the already
   eager-loaded `sessionAdaptations` collection, and calls
   `engine->resolveConsequencePath()`.
3. Loads the current session's `session_close_design`.
4. Passes both into `loadSessionContext()`.
5. Sets `$isClimacticThisTurn = (bool) $game->is_climactic_choice` — the
   value written by the PREVIOUS turn. When true, this is the aftermath/close
   turn and the authored close block is injected.
6. Passes `isClimacticThisTurn` into `renderSystemPrompt()`.

New private helper `extractSessionNumber(string $choiceId): int` — parses
`/^S(\d+)_/i` to recover session number from choice_id format.

---

### 4. `app/Http/Controllers/User/GameController.php`

On session transition (`nextSession()`):

1. Same consequence path resolution as PromptController.
2. If `$resolvedConsequencePath['next_session_opening']` is non-empty, it
   **replaces** `$openingHandoff` (which was previously always the generic
   `arc_progression.opens_with`). The consequence map's `next_session_opening`
   is authored specifically for the player's chosen path — tone, first image,
   first character, immediate stakes — and is always more precise than the
   generic handoff.
3. Loads the next session's `session_close_design`.
4. Passes both into `loadSessionContext()`.

Also updated the `begin()` call (session 1 opening) to pass
`isClimacticThisTurn: false` — no consequence path on session 1 start.

New private helper `extractSessionNumber()` — identical to the one in
PromptController. (Could be moved to ChaosEngineService in a future cleanup.)

## What Does NOT Change

- The adaptation pipeline — no re-runs required for the wiring.
- `ChaosNarrationSchema` — no new output fields.
- The `session_complete` signal — the model still decides this; the close
  block guides it with authored content but does not hard-override.
- World state merging — unchanged. `world_state_delta` from the consequence
  map is injected as narrator guidance, not applied mechanically.
- All existing `renderSystemPrompt()` / `loadSessionContext()` callers
  (ChaosModeController, DumpChaosPromptCommand) — unaffected by default params.

## Data Flow After This Release

```
Player makes choice → defining_choice_id + defining_choice_line stored on game

Next turn (aftermath):
  is_climactic_choice = true (set last turn)
  → resolveConsequencePath(S2_C3, line) → path B matched
  → buildConsequenceEchoBlock(path B) → injected at CONSEQUENCE_ECHO
  → buildSessionCloseBlock(session_close_design) → injected at SESSION_CLOSE
  → Model delivers authored resolution prose + session-end choice
  → session_complete = true

Next session start:
  resolvedConsequencePath['next_session_opening'] → replaces generic handoff
  → Session 3 opens on the authored consequence-specific scene for path B
  → buildConsequenceEchoBlock(path B) → still injected (narrator knows to honour payoff)
```

## What Still Needs To Happen

**1. RuntimeNarratorAssemblyJob backfill for all existing adapted stories.**

The two new tokens are not yet in any stored `runtime_narrator_prompt`.
Until this runs, all stories degrade gracefully to pre-V2.3.2 behaviour
(consequence echo and authored close are not injected). No data is lost.

```bash
php artisan tinker --execute='
$stories = App\Models\Story::whereHas("adaptation.sessionAdaptations", function($q) {
    $q->whereNotNull("runtime_narrator_prompt");
})->get();
foreach ($stories as $story) {
    $sessions = $story->adaptation->sessionAdaptations()->orderBy("session_number")->get();
    foreach ($sessions as $sa) {
        App\Jobs\Adaptation\RuntimeNarratorAssemblyJob::dispatchSync($story, $sa->session_number);
        echo $story->slug . " S" . $sa->session_number . " rebuilt\n";
    }
}
echo "Done\n";
'
```

$game = App\Models\Game::whereNotNull("defining_choice_id")->first();
