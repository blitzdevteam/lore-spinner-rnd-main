# V2.3.2 — Consequence Map & Session Close Wiring

**Status:** Planned  
**Identified:** Jun 29 2026  
**Priority:** High — core adaptive narrative contract is not being fulfilled in production

---

## What This Document Is

The adaptation pipeline produces two rich data structures per session —
`choice_consequence_map` and `session_close_design` — that are never read
during live gameplay in the production `PromptController` / `GameController`
flow. The model improvises both the session ending and the downstream
consequence of player choices, instead of executing the authored design.

This document is the complete, line-by-line engineering plan to wire both
into production. It is written to be executed in a single careful pass.

---

## Part 1 — The Two Gaps

### Gap A: `session_close_design` is ignored at runtime

**What it contains** (`session_close_design` on `session_adaptations`):

```
session_close_trigger_event_position  int        authored exit-point event position
resolution_prose                      string     120–200 words of authored payoff
hook_transition                       string     2–3 sentences bridging to end choice
session_end_choice {
    choice_question                   string
    option_a { text, next_session_opens }
    option_b { text, next_session_opens }
    option_c { text, next_session_opens }
    final_line                        string     last words of the session
}
stickiness_audit { payoff_test, return_driver_test, overnight_test }
```

**What happens without it:** The model decides alone when and how to close
the session based on Section 16 of the runtime template ("You decide when
the episode has naturally closed"). It improvises the resolution prose, the
session-end choice, and the final line. The authored close is sitting unused.

**The PlaygroundController already shows the pattern:** At turn 0 it checks
`session_close_trigger_event_id` against the current event and, if matched,
passes `sessionCloseDesign` into the system prompt. The production game flow
has no equivalent.

**The production gap:** The production game is turn-based (no event tracking
by position). The trigger mechanism must be different. Instead of
`trigger_event_position`, the production close should be triggered by
`is_climactic_choice === true` (the model already sets this on the turn it
resolves a session-end hook choice). When that flag is true on the CURRENT
turn, we inject the close design into the system prompt so the model delivers
the authored resolution prose and `session_end_choice` instead of
inventing one.

---

### Gap B: `choice_consequence_map` is never consulted

**What it contains** (keyed by `choice_id`, e.g. `S2_C3`):

```
branching_consequences[] {
    choice_id                         e.g. "S2_C3"
    tracked_dimension                 what this choice tracks
    is_session_end_hook               bool
    paths[A, B, C] {
        label                         A / B / C
        alignment                     CHAOTIC / LAWFUL / NEUTRAL
        immediate_effect
        current_session_echo          how to echo this turn's consequences this session
        next_session_payoff           what the narrator must honour in the NEXT session
        next_session_opening          tone/image/stakes for the opening of the next session
        later_session_legacy
        defining_line_captured
        consequence_visibility {
            what_changes
            when_visible_target_responses  (target: 2)
            when_visible_max_responses     (hard max: 3)
            how_player_sees_it
        }
        world_state_delta { inventory, npc_shifts[], environmental_flags[], alignment_shift }
        reactivity_triggers[]
        cross_episode_propagation { resets[], persists[], escalates[] }
    }
}
freeform_guidelines[] {            (12 entries — 4 choices × 3 paths)
    choice_id
    path_label
    narrator_behavior              how to surface this path's past choice going forward
    spirit
    fold_back_acknowledge
    fold_back_redirect
    fold_back_arrive_at
    hard_limits[]
}
```

**What the `game` model already stores:**
- `defining_choice_id` — e.g. `"S2_C3"` — which branching choice resolved
- `defining_choice_line` — the exact defining line for the chosen path

**What happens without it:** The game knows the player chose `S2_C3`, but
the next session opens the same way for every player. `next_session_payoff`
and `next_session_opening` are never injected. The `freeform_guidelines`
narrator_behavior (how to surface past choices) is never consulted. Choices
are recorded but don't branch the narrative forward.

**The gap:** `defining_choice_id` encodes both the session number and choice
number (e.g. `S2_C3` = session 2, choice 3). The path (A/B/C) is not stored —
it is recoverable by matching `defining_choice_line` against
`defining_line_captured` in each path entry of the consequence map. Once the
path is resolved, `next_session_payoff`, `narrator_behavior`, and
`consequence_visibility` are injected into the session start system prompt.

## Part 2 — The Fix

### What changes

Five things change. All changes are additive — no existing injection points
are removed or altered.

1. `ChaosEngineService::loadSessionContext()` — returns two new keys
2. `ChaosEngineService::renderSystemPrompt()` — handles two new injection points
3. `PromptController::store()` — passes `is_climactic_choice` flag and consequence data into `renderSystemPrompt()`
4. `GameController::nextSession()` — resolves consequence data for the incoming session
5. `runtime-narrator-template.blade.php` — two new injection point tokens in Section 13 / Section 10A

### New injection point tokens

```
[CONSEQUENCE_ECHO_INJECTION_POINT]     injected on EVERY turn when a defining_choice_id exists
[SESSION_CLOSE_INJECTION_POINT]        injected ONLY when is_climactic_choice = true (close turn)
```

Both tokens live in the pre-built `runtime_narrator_prompt` (baked at
adaptation time). They are resolved at runtime by `renderSystemPrompt()`.
If no consequence data exists (session 1, no choices yet), they are replaced
with an empty string.

## Part 3 — Precise File Changes

### 3A. `runtime-narrator-template.blade.php`

**Location:** `resources/views/ai/agents/chaos/runtime-narrator-template.blade.php`

**Change 1:** After Section 10 (Current Arc Position), add a new Section 10A:

```
### SECTION 10A: CONSEQUENCE ECHO [RUNTIME]

[CONSEQUENCE_ECHO_INJECTION_POINT]

---
```

This token is replaced at runtime with the active consequence guidance for
this session based on the player's last defining choice, or empty string if
no choice has been recorded yet.

**Change 2:** In Section 16 (Session-Complete Signal), before the existing
hardcoded instruction, add:

```
[SESSION_CLOSE_INJECTION_POINT]

```

This token is replaced with the authored close block (resolution prose +
hook transition + session_end_choice) when `is_climactic_choice` is true,
or empty string otherwise. The hardcoded Section 16 instruction remains
below it as a fallback for sessions where the close design is absent.

> **Why the template, not just the service?**
> The tokens live in the pre-assembled `runtime_narrator_prompt` (already
> stored in the DB). The service cannot inject text at arbitrary positions
> in the prompt — it can only replace tokens it knows exist. Adding them to
> the template ensures they are baked in during the next adaptation run.
> Existing stories already adapted will need a `RuntimeNarratorAssemblyJob`
> re-run to pick up the new tokens (see Part 5).

**New private method: `buildConsequenceEchoBlock()`**

```php
private function buildConsequenceEchoBlock(?array $path): string
{
    if ($path === null) {
        return '';
    }

    $lines = ['ACTIVE CONSEQUENCE GUIDANCE (player\'s prior defining choice):'];

    if (!empty($path['current_session_echo'])) {
        $lines[] = 'Echo this session: ' . $path['current_session_echo'];
    }
    if (!empty($path['next_session_payoff'])) {
        $lines[] = 'Honour this session: ' . $path['next_session_payoff'];
    }
    if (!empty($path['narrator_behavior'])) {
        $lines[] = 'Narrator behaviour: ' . $path['narrator_behavior'];
    }
    if (!empty($path['consequence_visibility']['what_changes'])) {
        $vis = $path['consequence_visibility'];
        $lines[] = 'Make visible within ' . ($vis['when_visible_target_responses'] ?? 2)
            . ' responses: ' . $vis['what_changes']
            . ' (' . ($vis['how_player_sees_it'] ?? '') . ')';
    }
    if (!empty($path['fold_back_acknowledge'])) {
        $lines[] = 'Fold-back: acknowledge "' . $path['fold_back_acknowledge']
            . '", redirect via "' . ($path['fold_back_redirect'] ?? '') . '"';
    }
    if (!empty($path['hard_limits'])) {
        $lines[] = 'Hard limits at this node: '
            . implode(' / ', (array) $path['hard_limits']);
    }

    return implode("\n", $lines);
}
```

**New private method: `buildSessionCloseBlock()`**

```php
private function buildSessionCloseBlock(?array $closeDesign): string
{
    if ($closeDesign === null) {
        return '';
    }

    $lines = ['AUTHORED SESSION CLOSE — deliver this, do not improvise:'];

    if (!empty($closeDesign['resolution_prose'])) {
        $lines[] = '';
        $lines[] = 'RESOLUTION PROSE (deliver verbatim, in the author\'s voice):';
        $lines[] = $closeDesign['resolution_prose'];
    }
    if (!empty($closeDesign['hook_transition'])) {
        $lines[] = '';
        $lines[] = 'HOOK TRANSITION:';
        $lines[] = $closeDesign['hook_transition'];
    }

    $choice = $closeDesign['session_end_choice'] ?? null;
    if ($choice !== null) {
        $lines[] = '';
        $lines[] = 'SESSION-END CHOICE QUESTION: ' . ($choice['choice_question'] ?? '');
        foreach (['option_a', 'option_b', 'option_c'] as $opt) {
            if (!empty($choice[$opt]['text'])) {
                $lines[] = '  ' . strtoupper($opt) . ': ' . $choice[$opt]['text'];
            }
        }
        if (!empty($choice['final_line'])) {
            $lines[] = '';
            $lines[] = 'FINAL LINE (last words of this session): ' . $choice['final_line'];
        }
    }

    return implode("\n", $lines);
}
```

### 3D. New private helper: `resolveConsequencePath()`

**Location:** `app/Services/ChaosEngineService.php` — new public method

This is the core resolution logic. Given a `defining_choice_id` (e.g. `"S2_C3"`),
a `defining_choice_line`, and the `choice_consequence_map` of the session
where that choice was made, it returns the full path array (A, B, or C).

```php
/**
 * Resolve which consequence path (A/B/C) the player took for a given
 * defining_choice_id by matching defining_choice_line against
 * defining_line_captured in each path.
 *
 * Returns the merged path array from both branching_consequences and
 * freeform_guidelines for the matched path, or null if unresolvable.
 *
 * @param  array<string, mixed>  $consequenceMap  — session_adaptations.choice_consequence_map
 * @return array<string, mixed>|null
 */
public function resolveConsequencePath(
    string $definingChoiceId,
    string $definingChoiceLine,
    array $consequenceMap,
): ?array {
    if ($definingChoiceId === '' || $definingChoiceLine === '') {
        return null;
    }

    // Find the branching consequence entry for this choice_id.
    $branchingEntry = null;
    foreach ((array) ($consequenceMap['branching_consequences'] ?? []) as $bc) {
        if (strtolower((string) ($bc['choice_id'] ?? '')) === strtolower($definingChoiceId)) {
            $branchingEntry = $bc;
            break;
        }
    }

    if ($branchingEntry === null) {
        return null;
    }

    // Match the path by comparing defining_choice_line against defining_line_captured.
    $matchedPath = null;
    $normalise   = fn (string $s): string => strtolower(trim(preg_replace('/\s+/', ' ', $s)));
    $needle      = $normalise($definingChoiceLine);

    foreach ((array) ($branchingEntry['paths'] ?? []) as $path) {
        $captured = $normalise((string) ($path['defining_line_captured'] ?? ''));
        if ($captured !== '' && str_contains($captured, $needle) || str_contains($needle, $captured)) {
            $matchedPath = $path;
            break;
        }
    }

    // Fuzzy fallback: first path if line matching fails (should not happen
    // if adaptation ran correctly, but prevents a hard null on mismatch).
    if ($matchedPath === null && !empty($branchingEntry['paths'])) {
        $matchedPath = $branchingEntry['paths'][0];
    }

    if ($matchedPath === null) {
        return null;
    }

    // Merge freeform_guidelines for this choice_id + path_label.
    $pathLabel  = strtoupper((string) ($matchedPath['label'] ?? ''));
    $freeform   = null;
    foreach ((array) ($consequenceMap['freeform_guidelines'] ?? []) as $fg) {
        if (
            strtolower((string) ($fg['choice_id'] ?? '')) === strtolower($definingChoiceId)
            && strtoupper((string) ($fg['path_label'] ?? '')) === $pathLabel
        ) {
            $freeform = $fg;
            break;
        }
    }

    return array_merge($matchedPath, $freeform ?? []);
}
```

> **Note on close trigger timing:**
> `is_climactic_choice` is set to `true` by the model on the turn it resolves
> a session-end hook choice. That same turn's response is the CLIMACTIC turn.
> The authored close (resolution prose + final choice) should be delivered on
> the turn AFTER the climactic choice — the "aftermath" turn. So
> `isClimacticThisTurn` is set to `(bool) $game->is_climactic_choice` (read
> from DB before the current turn fires), which is the value set on the
> PREVIOUS turn. This matches the natural narrative flow: climactic choice →
> player sees response → player acts → close is delivered.

**4. New private helper `extractSessionNumber()`:**

```php
/**
 * Extract session number from a choice_id like "S2_C3" → 2.
 */
private function extractSessionNumber(string $choiceId): int
{
    if (preg_match('/^S(\d+)_/i', $choiceId, $matches)) {
        return (int) $matches[1];
    }
    return 1;
}
```

## Part 5 — Template Token Backfill

The new injection point tokens (`[CONSEQUENCE_ECHO_INJECTION_POINT]`,
`[SESSION_CLOSE_INJECTION_POINT]`) must exist in the `runtime_narrator_prompt`
stored on each `session_adaptations` row for them to be replaced at runtime.

**For newly adapted stories:** The updated template automatically includes
them from the next adaptation run onward.

**For already-adapted stories (Matrix, Oz, Anima, etc.):** A targeted
`RuntimeNarratorAssemblyJob` re-run is required per story. This job
re-renders the template and overwrites `runtime_narrator_prompt`. It does
NOT re-run any AI calls — it is a pure PHP template re-render.

```bash
# Re-run assembly for all adapted stories
php artisan tinker --execute='
foreach (App\Models\Story::whereHas("adaptation")->get() as $story) {
    $sessions = $story->adaptation->sessionAdaptations;
    foreach ($sessions as $sa) {
        App\Jobs\Adaptation\RuntimeNarratorAssemblyJob::dispatchSync($story, $sa->session_number);
        echo $story->slug . " S" . $sa->session_number . " rebuilt\n";
    }
}
'
```

If the tokens do not yet exist in a `runtime_narrator_prompt`,
`strtr()` will simply find nothing to replace and the string is returned
unchanged — no error, no data loss. The feature degrades gracefully to
the current (no-consequence) behaviour for un-rebuilt stories.
